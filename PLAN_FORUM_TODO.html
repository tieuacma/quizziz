Tài liệu kế hoạch/roadmap chi tiết cho tính năng “Diễn đàn học tập” (Forum) gồm PRD, Database schema, API, UI/UX, acceptance criteria và ghi chú triển khai.
Trạng thái: Đã hoàn thiện Sprint 1–2 (API route handlers + UI skeleton + docs cơ bản); Sprint 3–5 đang tiếp tục

1) Mục tiêu

Thiết kế đặc tả chức năng (PRD) + giải pháp thiết kế (Database / Backend API / UI-UX) cho tính năng Diễn đàn học tập trên nền tảng giáo dục.
  • User flow rõ ràng cho đăng bài (có/không ẩn danh) và trạng thái bị kiểm duyệt.
  • Database schema cho Users, Posts, Comments, Votes, Reports (dùng MongoDB driver, không ORM).
  • API bao phủ: CRUD bài viết, threaded comments, vote, chọn “đáp án hữu ích/đúng”, report, moderation (approve/reject/block), auto-moderation bằng AI/bộ lọc.
  • UI/UX component list cho trang diễn đàn: list/filter/sort, composer editor, post detail + comment tree, report modal, moderation queue.

2) Thu thập ngữ cảnh dự án (Repo reconnaissance)

2.1 Các điểm cần kiểm tra

  • [ ] Xem cấu trúc routes hiện có trong app/ và pattern dashboard.
  • [ ] Đọc phần auth/session: lib/session.ts, app/actions/auth.ts để hiểu cách lấy user/role.
  • [ ] Xác định cách truy cập MongoDB hiện tại: lib/mongodb.ts.
  • [ ] Nhận diện style/UI component pattern đang dùng: components/ui/*, app/globals.css.

2.2 Kết quả cần có

  • Ghi nhận cách app xử lý user/role (student/teacher/admin) và dùng session cookie.
  • Ghi nhận pattern để viết backend logic: Server Actions vs Route Handlers (API routes).
  • Ghi nhận pattern upload file (nếu repo có sẵn) hoặc quyết định hướng triển khai.

3) Phân tích nghiệp vụ & phạm vi chức năng (Business analysis)

3.1 Actors & quyền hạn

  • [ ] Xác định actors: học sinh, giáo viên, admin/moderator.
  • [ ] Xác định các quyền theo role: xem/nộp bài, comment, vote, report, phê duyệt, xoá/cảnh cáo.
  • [ ] Xác định nguyên tắc ẩn danh: frontend che “Học sinh ẩn danh”, backend vẫn giữ userId.

3.2 Use cases chính

  • [ ] Đăng bài: text + images + file đính kèm (PDF/Word) + chèn công thức (LaTeX/MathJax/KaTeX—chốt công nghệ).
  • [ ] Threaded comments: comment đa cấp để theo dõi hội thoại.
  • [ ] Vote/Emotion: like/dislike hoặc upvote/downvote cho bài và comment (chốt 1 trong 2).
  • [ ] Đánh dấu “câu trả lời đúng/hữu ích nhất”: chỉ tác giả bài viết hoặc giáo viên được chọn (chốt rule rõ).
  • [ ] Report: người dùng flag bài/comment vi phạm, gửi lý do.
  • [ ] Moderation: auto-moderation (AI/bộ lọc) → trạng thái bài/comment “Chờ duyệt/Bị chặn”; admin approve/reject/block.

3.3 Invariant (quy tắc dữ liệu/role)

  • [ ] Một user chỉ có thể vote một giá trị trong cùng scope (bài hoặc comment).
  • [ ] Accepted/Best answer: tối đa 1 accepted cho mỗi post (hoặc định nghĩa rõ số lượng).
  • [ ] Moderation state phải đồng bộ với hiển thị UI (không lộ nội dung khi bị chặn).
  • [ ] Anonymous vẫn ghi userId cho audit/moderation nhưng che trên UI.

4) Brainstorm & thiết kế kiến trúc giải pháp

4.1 PRD chi tiết

  • [ ] User flow đăng bài: gồm luồng ẩn danh + luồng bị kiểm duyệt.
  • [ ] Acceptance criteria cho từng tính năng nhỏ.
  • [ ] Định nghĩa định dạng “content” bài viết/comment: text + rich media + math markup.

4.2 Database Schema (Mongo collections)

Thiết kế cơ bản cho các collections: Users, Posts, Comments, Votes, Reports (có thể thêm collection phụ như ModerationEvents, AutoModerationLogs).
  • [ ] Chuẩn hoá field: createdAt, updatedAt, authorId, visibility, moderationStatus.
  • [ ] Index gợi ý: theo postId, createdAt, moderationStatus, userId, parentCommentId.
  • [ ] Thiết kế hierarchical comments: store parentCommentId + optional path/thread để query.

4.3 Backend API (Route Handlers / Server Actions)

  • [ ] Posts: create, edit, delete (soft delete), list, get detail.
  • [ ] Comments: create threaded comment, list by post, delete/edit theo quyền.
  • [ ] Votes: vote/unvote, thống kê like/dislike/up/down, đảm bảo idempotent.
  • [ ] Accepted answer: set/unset best/accepted (rule theo tác giả/teacher).
  • [ ] Reports: create report for post/comment + deduplicate (user+target+reason window).
  • [ ] Moderation: approve/reject/block + audit trail.
  • [ ] Auto-moderation: AI/bộ lọc → score/labels → quyết định state (“Chờ duyệt” hoặc “Bị chặn”).

4.4 UI/UX components

  • [ ] Forum landing: search, filter theo lớp/trường, sort (hot/new/top), pagination.
  • [ ] Post composer: toggle anonymous, nhập title/body, upload image/file, checkbox đính kèm math.
  • [ ] Post detail: render math, attachments, best answer badge, vote panel.
  • [ ] Comment tree: reply button, show/hide deleted comments, nested indentation.
  • [ ] Report modal: chọn reason, mô tả thêm, submit.
  • [ ] Moderation queue (admin): list chờ duyệt, approve/reject/block, view evidence.
  • [ ] Trạng thái bài bị kiểm duyệt: UI hiển thị “Chờ duyệt/Bị chặn”.

4.5 Mapping yêu cầu ↔ Database ↔ API ↔ UI

  • [ ] Lập bảng mapping để đảm bảo mỗi requirement có ít nhất 1 collection field + 1 endpoint + UI state tương ứng.

5) Deliverables (Tài liệu đầu ra)

  • [ ] PRD hoàn chỉnh theo các mục trong yêu cầu của người dùng.
  • [ ] Database schema: mô tả field + kiểu dữ liệu + index.
  • [ ] API spec: endpoint list + request/response shape (mức detail hợp lý).
  • [ ] UI component list: tên component + props/state + behavior.
  • [ ] Nêu rõ quyền truy cập theo role (auth guard).
  • [ ] Ghi chú các quyết định kiến trúc quan trọng: index, consistency, moderation states, audit logs.

6) Rà soát tính khả thi & chuẩn dự án (Feasibility)

  • [ ] Tương thích session/auth hiện tại (cookie-based demo; sau đó mapping sang production).
  • [ ] Phù hợp Mongo driver + patterns server actions trong repo.
  • [ ] UX: loading/error/optimistic update cho vote, và trạng thái moderation cho composer/post detail.
  • [ ] Security: validate upload (type/size), rate limit tạo bài/comment, chống spam.
  • [ ] AI moderation: mô tả pipeline, cách lưu log/score, xử lý false positive.

7) Kiểm thử & Acceptance criteria (mức tài liệu)

  • [ ] Đăng bài: ẩn danh hiển thị đúng; backend vẫn có audit.
  • [ ] Moderation: nội dung bị lọc → đổi state hiển thị “Chờ duyệt/Bị chặn”.
  • [ ] Threaded comments: tạo trả lời đa cấp; hiển thị đúng cây hội thoại.
  • [ ] Vote: idempotent, không vote trùng scope; thống kê đúng.
  • [ ] Accepted answer: rule áp dụng đúng role; chỉ 1 accepted (hoặc định nghĩa).
  • [ ] Report: chống spam report trùng; admin xử lý report tương ứng target.
  • [ ] Moderation actions: approve/reject/block đảm bảo không lộ nội dung.
