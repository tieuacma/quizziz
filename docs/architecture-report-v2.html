🏗️ 1. Tổng quan kiến trúc

Zenith EDU là ứng dụng web monolith full-stack được xây dựng trên Next.js 16 App Router, kết hợp giữa Server Components và Client Components để tối ưu hiệu năng và trải nghiệm người dùng.

Kiến trúc được tổ chức theo mô hình 3 tầng rõ ràng, tách biệt mối quan tâm giữa presentation, business logic và data access:

🎨 Tầng Presentation

  • app/ — Định nghĩa routes, layouts, metadata
  • components/ — UI components theo domain (landing, dashboard, quiz-game, exam, editor)
  • public/ — Static assets (SVG, images)

⚙️ Tầng Application

  • app/actions/ — Server Actions (auth, quiz CRUD, exam submission)
  • lib/ — Business logic (MongoDB, session, grading, normalization)
  • hooks/ — Custom React hooks (useQuizEditor, useQuizLogic)
  • stores/ — Zustand global state (exam-store với persist)

💾 Tầng Data

  • MongoDB — Collection quizzes (production data)
  • data/quiz.json — Fallback & seed data
  • Mock data — Dashboard static data (development)

• (auth)/ — Route group cho login/signup (không ảnh hưởng URL)

• ui/ — Primitive components (Button, Card, Input từ Radix)

• mongodb.ts — Singleton connection pool

• getExamData.ts — Sanitize quiz data cho exam mode

• useQuizEditor.ts — State management cho quiz editor

stores/ Global State (Zustand):

types/ TypeScript Definitions:

• Bảo vệ /dashboard/* (yêu cầu session)
• Redirect user đã login khỏi /login, /signup

Lưu ý: Dự án không sử dụng app/api/ (Route Handlers). Mọi thao tác ghi/đọc có xác thực đều đi qua Server Actions với directive "use server".

    Action-->>Client: { success: false,

(so sánh từng câu)

score, correctCount,

  end

3.3. Luồng thi & chấm điểm chi tiết

📝 Trong lúc làm bài

  • ExamClient (client) render câu hỏi từ data đã sanitize
  • Mỗi câu trả lời → useExamStore.setAnswer() → persist localStorage
  • Timer đếm ngược từ examTimeLimit (metadata)
  • Flag câu hỏi để xem lại sau

📤 Khi nộp bài

  • submitExamAction nhận: quizId, answers[], startedAt, finishedAt
  • Server load full quiz (có correctAnswer) từ MongoDB
  • isQuestionCorrect() so sánh từng loại câu hỏi
  • Trả về: score, correctCount, items (với explanation)

/(auth)/login
/(auth)/signup 		CSR Client forms → Server Actions (auth.ts) → redirect

🔒 6. Bảo mật & Phiên đăng nhập

Hệ thống áp dụng multi-layer security với kiểm tra ở cả Edge, Server layout, và Server Actions.

🔀 Lớp 1 — proxy.ts (Edge Gateway)

  • Chặn /dashboard/* nếu không có cookie session
  • Redirect user đã login khỏi /login, /signup
  • Hoạt động như middleware-style routing

🖧 Lớp 2 — Server Layout

  • dashboard/layout.tsx gọi lại getSession() và redirect
  • Trang con kiểm tra session.role (teacher vs student)
  • Server-side rendering an toàn (không expose session cho client)

📝 Lớp 3 — Thi thử (/do-exam)

  • Server strip đáp án đúng (sanitizeQuestion()) trước khi render
  • submitExamAction load full quiz trên server để chấm
  • Client không bao giờ thấy correctAnswer trong exam mode

🎮 Lớp 4 — Quiz Game (/quiz-game)

  • Gửi full questions (có đáp án) — phù hợp luyện tập
  • Không phải chế độ thi bảo mật
  • Score tính client-side (có thể cheat — acceptable cho practice)

Session Management

Hiện tại dùng cookie-based session với base64-encoded JSON:

  • Cookie name: session
  • Encoding: Base64(JSON({ userId, email, name, role }))
  • HttpOnly: ✅ (không thể đọc từ JS)
  • Secure: ✅ (chỉ gửi qua HTTPS trong production)
  • SameSite: Lax (chống CSRF)
  • MaxAge: 7 days
⚠️ Lưu ý: Auth demo chưa production-ready. Cookie session không có signature/encryption — người dùng có thể forge session. Production cần tích hợp Supabase Auth hoặc NextAuth.js với JWT signing.

💡 8. Đánh giá & Khuyến nghị

✅ Điểm mạnh

  • Tách rõ chế độ luyện tập (quiz-game) vs thi bảo mật (do-exam)
  • Server Actions giảm boilerplate API routes
  • Repository pattern cho MongoDB — dễ maintain
  • Zustand persist — exam state survive page reload
  • Sanitization layer — strip đáp án trước khi render exam
  • JSON fallback — graceful degradation khi Mongo chưa có data

⚠️ Cần lưu ý

  • Auth demo chưa production-ready (cookie không signature)
  • Dashboard mock data chưa đồng bộ với MongoDB thật
  • Trùng code giữa src/ và lib/
  • Không có caching — mọi request đều query DB
  • Không có rate limiting cho Server Actions
  • Exam store persist có thể bị clear khi user clear localStorage

🚀 Gợi ý phát triển

  • Tích hợp Supabase Auth — JWT signing, refresh tokens
  • Thêm ISR/cache tags cho danh sách quiz public
  • Persist kết quả thi vào MongoDB (hiện chỉ trả về client)
  • Real-time leaderboard với WebSocket/Server-Sent Events
  • Export quiz ra PDF/Word cho giáo viên
  • Question bank — tái sử dụng câu hỏi giữa các quiz
  • Analytics dashboard — thống kê performance học sinh
  • Anti-cheat — detect tab switching trong exam mode

Architecture Decision Records (ADRs)

✅ Server Actions over API Routes: Giảm complexity, type-safe end-to-end, không cần serialize/deserialize qua HTTP boundary.
✅ MongoDB over SQL: Schema linh hoạt cho quiz questions (nested reading passages, variable options per question), dễ evolve question types.
⚠️ Cookie Session over JWT: Đơn giản cho demo nhưng không secure cho production — cần migrate sang JWT với signature verification.
