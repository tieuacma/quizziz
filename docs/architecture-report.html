1. Tổng quan kiến trúc

Zenith EDU là ứng dụng web monolith full-stack trên Next.js App Router. Kiến trúc tách rõ ba tầng logic:

Tầng Presentation

Thư mục app/ (routing) và components/ (UI theo domain: landing, dashboard, quiz-game, exam, editor).

Tầng Application

app/actions/ (Server Actions), lib/ (repository, grading, session), hooks/ + stores/ (client state).

Tầng Data

MongoDB collection quizzes, fallback file data/quiz.json, dữ liệu demo tĩnh trong dashboard.

Edge / Gateway

proxy.ts — kiểm tra cookie session trước khi vào /dashboard (thay middleware cũ trên Next.js 16).

2. Cấu trúc thư mục chính

Thư mục / File Vai trò
app/ Định nghĩa route, layout, metadata. Nhóm route: (auth), dashboard/*, quiz-game, do-exam, quiz-editor, quiz-create.
app/actions/ Server Actions: xác thực (auth.ts), CRUD quiz MongoDB (quiz-mongodb.ts), nộp bài thi (submit-exam-action.ts).
components/ UI tái sử dụng theo feature: landing/, dashboard/, quiz-game/, quiz-editor/, do-exam/, ui/ (Radix/shadcn-style).
lib/ Logic server-side: kết nối MongoDB, repository quiz, chuẩn hóa document, chấm điểm thi, session cookie, lịch giảng dạy.
hooks/ Custom hooks phía client: useQuizEditor, useQuizLogic, useTeachingSchedule.
stores/ Zustand + persist: trạng thái làm bài thi (exam-store.ts) lưu localStorage.
types/, models/ Định nghĩa TypeScript cho quiz, session, shape document Mongo (không dùng ORM).
data/ File JSON dự phòng khi Mongo chưa có dữ liệu; tự seed vào DB khi load quiz.
scripts/ Tiện ích CLI: seed Mongo, migrate schema phẳng, debug lookup.
proxy.ts Gateway request: bảo vệ /dashboard, chuyển hướng auth đã đăng nhập.
src/ Bản sao/legacy của một số action và service — nên ưu tiên import từ lib/ và app/actions/.
public/ Tài nguyên tĩnh (SVG, assets).

3. Luồng hoạt động (Data Flow)

3.1. Request HTTP → Response HTML

sequenceDiagram
  participant B as Browser
  participant P as proxy.ts
  participant R as App Router
  participant SC as Server Component
  participant DB as MongoDB

  B->>P: GET /do-exam/abc
  P->>P: Kiểm tra cookie session (nếu /dashboard)
  P->>R: NextResponse.next()
  R->>SC: do-exam/[id]/page.tsx
  SC->>DB: findQuizById(id)
  DB-->>SC: Quiz document
  SC->>SC: sanitizeQuestion — loại đáp án đúng
  SC-->>B: HTML + RSC payload + ExamClient (client)
  B->>B: Hydrate, Zustand persist answers

3.2. Mutation qua Server Actions

Dự án không có thư mục app/api/ (Route Handlers). Mọi thao tác ghi/đọc có xác thực đi qua Server Actions với directive "use server". 

sequenceDiagram
  participant C as Client Component
  participant SA as Server Action
  participant S as lib/session
  participant M as MongoDB

  C->>SA: submitExamAction({ quizId, answers })
  SA->>S: getSession()
  alt Không có session
    SA-->>C: { success: false, error: Unauthorized }
  else Có session
    SA->>M: findQuizById (đáp án đầy đủ)
    SA->>SA: exam-grading — isQuestionCorrect
    SA-->>C: score, items, explanations
  end

3.3. Luồng biên soạn Quiz (Editor)

  1. Trang quiz-editor/[id] là Client Component.
  2. useQuizEditor gọi getQuizMongoAction → Mongo hoặc seed từ data/quiz.json.
  3. Lưu: updateQuizMongoAction → upsertQuiz trong lib/quiz-repository.ts.

4. Cơ chế Rendering (SSR / SSG / ISR)

Kết luận: Dự án chủ yếu dùng Dynamic Server-Side Rendering (mặc định App Router khi Server Component gọi DB/async). Không cấu hình revalidate, ISR, hay export const dynamic tường minh. Không có SSG thực tế cho route động quiz ( generateStaticParams trả về mảng rỗng).
Route / Trang Pattern Ghi chú
/ SSR + CSR Server page render LandingPage (client) — animation GSAP/Framer sau hydrate.
/dashboard/* SSR Layout async đọc getSession(); nhiều trang dùng mock data tĩnh import từ data.ts.
/quiz-game/[id] SSR getQuizById trên server → truyền initialQuestions xuống QuizGame (client, có đáp án — chế độ luyện tập).
/do-exam/[id] SSR getExamData strip đáp án đúng trước khi gửi client — chấm điểm chỉ trên server.
/quiz-editor/[id] CSR Toàn bộ editor client-side; fetch qua Server Action sau mount.
/quiz-game (demo) CSR Dữ liệu mẫu sample-data hard-coded.

5. Tương tác API & Dữ liệu

5.1. MongoDB

Kết nối singleton trong lib/mongodb.ts qua biến môi trường MONGODB_URI và MONGODB_DB (mặc định database quizzes). Collection chính: quizzes — document phẳng (title, questions[], id/slug).

  SA --> REPO
  REPO --> NORM
  REPO --> MONGO

  JSON["quiz-json-fallback.ts"] -.->|seed nếu thiếu| COL

5.2. Bảng Server Actions chính

Action File Chức năng
login, signup, logout app/actions/auth.ts Demo users in-memory → cookie session base64 JSON.
getQuizMongoAction, updateQuizMongoAction app/actions/quiz-mongodb.ts CRUD quiz cho editor; fallback JSON → Mongo seed.
submitExamAction app/actions/submit-exam-action.ts Chấm điểm server-side, yêu cầu session student/teacher.
getQuizzes, getQuizById, … lib/quiz-service.ts Service layer (cũng đánh dấu use server) cho game/preview.

5.3. Bên thứ ba & tích hợp dự kiến

  • Google Fonts — next/font (Geist, Plus Jakarta Sans) trong root layout.
  • Supabase Auth — được ghi chú trong code (proxy.ts, lib/session.ts) nhưng chưa tích hợp; hiện dùng cookie demo.
  • Không có REST API public, GraphQL, hay webhook outbound trong codebase hiện tại.

5.4. Chiến lược dữ liệu Dashboard

Phần lớn trang teacher/student dashboard hiển thị dữ liệu mock tĩnh từ app/dashboard/teacher/data.ts và app/dashboard/student/data.ts — chưa đồng bộ với MongoDB. Chỉ luồng quiz/exam/editor kết nối database thật.

6. Bảo mật & Phiên đăng nhập

Lớp 1 — proxy.ts

  • Chặn /dashboard/* nếu không có cookie session.
  • Redirect user đã login khỏi /login, /signup.

Lớp 2 — Server layout

  • dashboard/layout.tsx gọi lại getSession() và redirect.
  • Trang con kiểm tra session.role (teacher vs student).

Thi thử (/do-exam)

  • Server strip đáp án đúng trước khi render client.
  • submitExamAction load full quiz trên server để chấm.

Quiz game (/quiz-game)

  • Gửi full questions (có đáp án) — phù hợp luyện tập, không phải thi bảo mật.
